# 代码结构与维护

核对日期：2026-10-05。项目只依赖 Python 标准库，不需要 pip 安装第三方库。

## 模块职责

| 模块 | 职责 |
|---|---|
| `bot.py` | Telegram HTTP API、长轮询、主数据库、租户初始化和分发、验证、帮助、管理操作服务、消息删除队列、群主配置 |
| `moderation.py` | `/manage` 面板、黑白名单选择、按钮身份校验、拉黑确认、关闭与面板失效 |
| `jev_ads.py` | `/report`、后台 Jev 分类、群员投票、管理员驳回、确认后删广告并调用统一警告服务 |
| `appeals.py` | 私聊解封申请、群主审批、通知重试、统一解封调用 |
| `points.py` | 积分事件、北京时间每日额度、签到、发言积分、统计与排名 |
| `milestones.py` | 首次达标序号、前 50 名、祝贺补发 |
| `attention.py` | 完整三日只签到窗口、运行缺口保护、异常签到拉黑与清零积分 |
| `airdrop.py` | 空投命令、申请与审批、候选核验、多名中奖、开奖结果及历史 |
| `chain.py` | Base 区块获取、链 ID/时效检查和备用来源 |
| `bitcoin.py` | BTC 区块工具及历史兼容数据相关实现；新空投使用 Base |
| `ai_chat.py` | AI 请求、冷却、后台任务、并发、Markdown/HTML 转换和模型 ID |
| `history.py` | 群聊记录、回复链、话题过滤、上下文选取和淘汰 |
| `vision.py` | 图片/相册索引、Telegram 媒体下载和模型图片输入 |
| `members.py` | 已观察用户名与 ID 索引，操作前重新核验用户名 |
| `binlookup.py` | BIN 请求、缓存、错误和限流处理 |
| `scripts/command_descriptions.json` | Telegram 英文命令及中文说明 |
| `scripts/update_commands.py` | 更新已有菜单说明、移除不在命令表的条目，并迁移旧管理菜单到 `/manage` |
| `tests/` | 使用模拟 Telegram/API 和内存 SQLite 的回归测试 |

## 更新处理

```text
Telegram getUpdates
  → 控制层：群设置、群选择和多群登记
  → 根据消息群或按钮中的群 ID 选择启用租户
  → 租户：保存可用上下文、处理命令/验证/按钮
  → 主循环：后台 AI/Jev、验证到期、空投、通知及删除队列
  → 保存处理位置，继续长轮询
```

群消息按 chat ID 分发。管理、Jev、达标榜和解封等按钮携带所属群信息，接收后校验租户和权限。私聊积分查询先选择群；管理操作使用当前管理群，已打开的管理按钮仍绑定原群。

`Bot.call()` 统一发送 API 请求；群内普通 `sendMessage` 自动进入删除队列，交互消息通过 `keep=True` 暂缓普通清理。群内验证、审批、投票和管理面板各自负责在结束时安排清理。私聊不进入群内队列。

## 数据隔离

控制数据库默认位于 `/var/lib/tgbot/bot.sqlite3`，主群沿用它保存自身业务数据。其他群默认位于 `/var/lib/tgbot/groups/<群ID>/bot.sqlite3`。

| 数据类别 | 主要记录 |
|---|---|
| 控制层 | 群登记、启用状态、当前管理群和轮询位置 |
| 成员管理 | 验证、警告、违规事件、黑白名单、操作审计、面板与解封申请 |
| 积分活动 | 用户积分、积分事件、活动日、运行缺口、升级和首次达标 |
| 举报 | Jev 分类任务、案例状态、投票及卡片 |
| 空投 | 审批申请、开奖记录、中奖名单、候选顺序及区块证明 |
| AI | 冷却、后台任务、有限聊天记录、回复关系、媒体索引 |
| 清理 | 待删群消息、验证卡片、重试次数与到期时间 |

SQLite 数据和 `.env` 不放入 Git。数据库采用 WAL；备份应使用 SQLite backup API 或停服后完整复制，避免只复制正在写入的主文件。

## 状态与重试

- 警告用稳定事件 ID 去重；第三次处罚另记录 `punished`，通知失败重试不重复封禁。
- 解封先成功调用 Telegram，再清理本地状态；失败不丢失黑名单。
- 管理面板绑定群、打开它的管理员、消息与有效期；操作后旧按钮失效，警告使用面板 token 作为事件的一部分。
- Jev 分类与投票持久保存；相同源消息最多警告一次。接口失败不触发处罚。
- 空投保存区块、候选顺序和中奖结果；重试不更换区块或重新抽取。
- 达标序号与补发状态持久保存；标签修改和祝贺通知分别处理。
- 消息删除和通知采用有限重试；重启继续处理已保存的任务。

外部 API 和 SQLite 不能构成统一事务。因此仍需审计错误、保留失败状态并依赖事件去重，不能宣称所有外部调用严格只执行一次。

## 维护要求

1. 修改行为时同步 `FEATURES.md`、`COMMANDS.md`、`/help` 和相关测试。
2. 修改英文命令时同步命令说明 JSON，并在生产运行菜单更新脚本。该脚本维护已有菜单，不会从零创建整套菜单。
3. 中文普通文本别名独立维护，不恢复中文斜杠命令。
4. 新按钮必须校验所属群、消息、有效期、操作者及其当前权限；不能只信任 callback_data。
5. 用户操作源消息保留；群内普通回复走默认清理，交互卡片结束后恢复清理。
6. 数据库变更兼容已有数据库并保留迁移。当前迁移添加违规处罚标记，移除每日操作计数表及旧限制配置。
7. 发布前跑回归测试、检查配置和源代码中的凭据，使用不含 `.env`/数据库的源文件包部署。

测试命令、服务维护和恢复方法见 [DEPLOYMENT.md](DEPLOYMENT.md)。
