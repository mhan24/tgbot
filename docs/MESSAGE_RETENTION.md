# 消息保留与自动删除规范

版本：2.0 · 2026-11-04

本文是新增、修改机器人功能时必须遵守的消息生命周期规范。当前版本只包含入群验证功能，表内时长是现行工程默认值；新增功能（原石、抽卡）要接入时必须在这里登记自己的时间表。

## 1. 目标与原则

让用户能看懂结果、完成操作、修正错误，并在需要时核对处理记录。

1. **先确定消息用途，再决定保留时间。** 不按命令名称一刀切。
2. **用户源消息保留。** 命令、普通发言和私聊来信不因操作成功、失败、重复或取消而删除。
3. **处理中的提示不能提前消失。** 验证卡片必须保留到通过、拒绝或超时。
4. **成功提示必须对应实际成功。** 明确失败原因、是否已执行，并给出恢复路径。
5. **删除消息不等于删除业务数据。** 数据库、审计日志和消息界面分别管理。
6. **群组隔离。** 只处理配置群落的业务；按钮核验群、操作者、随机串与有效期。

## 2. 当前时间表

| 消息类别 | 保留规则 | 计时起点 |
|---|---|---|
| 群内普通成功提示、`/help` 及其他常规回复 | 默认 30 秒，按 `DELETE_AFTER_SECONDS` | 发送成功 |
| 群内失败提示、参数错误、未知命令提示 | 120 秒（`Bot.notice_seconds()`） | 发送成功 |
| 入群验证卡片 | 验证期间保留；通过、答错上限、超时或记录失效后按群常规时长清理 | 结束状态被处理 |
| 群内观察到的其他 Bot 消息 | 群常规时长；只处理实际送达本机器人的消息 | 收到消息 |
| 用户命令、普通发言、私聊来信 | 保留 | 不设置删除任务 |
| 私聊验证卡片 | 保留（不自动删除） | 不设置删除任务 |
| 频道身份发言 | 不清理、不处理 | — |

`DELETE_AFTER_SECONDS=0` 关闭群内自动清理，同时使 `Bot.notice_seconds()` 返回 0；此时验证卡片结束只删除 `verification_prompts` 记录，不再排队删除消息。

## 3. 开发接入方法

### 3.1 群内普通反馈

统一使用 `Bot.send()`，默认进入删除队列；失败、警告类通知必须**显式**给出时长：

```python
bot.send(bot.group, '操作成功。')                                   # 群常规时长
bot.send(bot.group, '尚未提供这个命令，发送 /help 查看可用功能。',
         _delete_after=bot.notice_seconds())                        # 120 秒
```

代码不按中文关键词、文案长度猜测类别；同一句文案在成功与失败路径上的时长由调用方声明。不要绕过封装直接调用 `api.call()` 发群消息。

### 3.2 交互卡片

```python
sent = bot.send(bot.group, card_text, keep=True, reply_markup=buttons)
# 业务结束后转入普通清理：
bot.schedule_delete(bot.group, sent['message_id'])
# 需要阅读的失败结果：
bot.schedule_delete(bot.group, sent['message_id'], seconds=bot.notice_seconds())
```

`keep=True` 表示这次发送不进入常规删除队列，**不意味着永远不会删除**；交互功能必须自己定义结束清理。`editMessageText` 不会自动排队删除，也不会重置计时。

验证卡片的做法可参考 `verification.py`：卡片发送后登记 `verification_prompts(chat, message_id, uid, nonce, expires)`，`Bot.queue_finished_cards()` 在维护时把已结束（通过、随机串更换、记录消失、超时）的卡片转入删除队列。

### 3.3 私聊

私聊消息目前不做自动清理：验证卡片是用户需要的操作说明，保留到用户自己处理。新增私聊流程若要清理旧提示，只能删除本机器人自己发出、并已记录消息 ID 的提示，不能删除用户消息。

## 4. 队列与失败处理

- 删除任务写入 `deletions(chat, message_id, attempts, due)`，每轮最多处理 50 条，重启后继续。
- 400/403 直接放弃（消息已删除或无权删除）；429 按 `retry_after` 延后；其他错误重试 2 次后放弃，并写 `delete_giveup` 审计。
- 到期时间只是目标时间：长轮询、网络延迟和限流都可能推迟实际删除。
- 删除失败不得用来隐藏错误、扣分或处罚依据。

## 5. 合入检查

新增或修改消息功能时逐项确认：

- [ ] 每条新消息都能归入上表某一类，或在本文件登记了新的保留规则。
- [ ] 失败提示使用 `_delete_after=bot.notice_seconds()`，成功提示用默认时长。
- [ ] 交互卡片有明确的开始、结束、超时和恢复路径，结束时由本功能安排清理。
- [ ] 私聊只清理本机器人记录过的旧提示，用户消息与最终结果保留。
- [ ] 群业务只使用配置群的实例与数据库，按钮重新校验群、操作者、随机串和有效期。
- [ ] 关闭自动清理（`DELETE_AFTER_SECONDS=0`）时行为仍有定义。
- [ ] 相关测试覆盖结束清理与关闭清理两种情况。
