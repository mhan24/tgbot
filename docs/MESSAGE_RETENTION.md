# 消息保留与自动删除规范

版本：1.1 · 2026-11-04

本文是新增、修改机器人功能时必须遵守的消息生命周期规范。当前生产规则由用户确认，本文不会因为模型评估而自行改变已确认的时间。代码接入要求见第 4 节，合入检查见第 6 节。

## 1. 目标与原则

让用户能看懂结果、完成操作、修正错误，并在需要时核对处理记录，同时减少群内重复提示。这里所说的“社会工程学”具体落实为注意力、认知负担、可恢复性和信任设计。

1. **先确定消息用途，再决定保留时间。** 不按命令名称一刀切。
2. **用户源消息保留。** 命令、填写参数、普通发言不因操作成功、失败、重复或取消而删除。
3. **处理中的提示不能提前消失。** 必须保留当前操作说明和有效按钮，直到完成、取消或明确的超时。
4. **有实际权益的结果保留。** 解封审批结果、处罚依据和私聊处理结果需要核对。
5. **成功提示必须对应实际成功。** 数据提交、扣分、报名等业务结果确定后才能通知成功。显示更新失败不得重复执行扣分或处罚。
6. **删除消息不等于删除业务数据。** 数据库、审计日志、积分账本和消息界面分别管理。
7. **群组隔离。** 使用所属群的 Bot 实例和配置，按钮核验群、操作者、会话、有效期与当前权限。

例外：确认广告后的删除、明确的成员处罚删消息，属于独立管理流程。需要权限核验、业务规则及审计，不能当成普通自动清理调用。

## 2. 当前采用的时间表

| 消息类别 | 保留规则 | 计时起点 |
|---|---|---|
| 普通群内成功提示、帮助、查询结果、达标祝贺 | 默认 30 秒，按本群 `DELETE_AFTER_SECONDS` | 发送成功 |
| 十连签到结果、五星常驻/五星 UP 群内播报 | 默认 30 秒，按本群 `DELETE_AFTER_SECONDS` | 各条发送成功 |
| 群内短失败提示、重复签到提示、警告和处罚通知 | 120 秒 | 发送成功 |
| 入群验证卡片 | 验证中保留；完成、失效或超时后按群常规时间清理 | 结束状态被处理 |
| Jev 投票卡片 | 待确认保留，最长 24 小时；确认广告、错误或过期后 120 秒，其他结束状态常规时间 | 结束并更新卡片 |
| `/manage` 面板 | 有效期 5 分钟，再加群常规时间；完成操作后旧面板常规时间清理，新面板重新计时 | 面板发送或旧面板被替换 |
| 主动点击关闭管理面板 | 立即删除机器人面板 | 关闭操作 |
| 私聊当前填写步骤 | 当前步骤期间保留，结束/下一步后 30 秒删除 | 下一步成功显示或结束填写 |
| 私聊最终预览、处理结果、常规查询结果 | 保留 | 不设置删除任务 |
| 用户命令、参数和普通消息 | 保留 | 不设置删除任务 |
| 能实际收到的其他 Bot 群消息 | 本群常规时间；不代表能读取所有 Bot 消息 | 收到消息 |

`DELETE_AFTER_SECONDS=0` 关闭本群常规自动清理及跟随该开关的普通失败/处罚通知。私聊旧步骤固定 30 秒；明确的关闭、广告或处罚删除是独立动作。

这些时长是工程默认值，不是经过实验验证的“最佳阅读时间”。旧提示只有在被替换或结束后才能开始清理，不能从整个会话开始时间统一倒计时。

## 3. 文案、阅读和恢复要求

### 3.1 减少必须记住的信息

成功反馈应简短，说清“发生了什么”，例如“参与成功，扣除 10 积分”。失败反馈说明“为什么失败、是否产生扣分/处罚、下一步怎么做”。不可仅发“ERROR”“失败”或要求用户猜测。

长说明、金额/积分明细或需要反复查阅的结果，不应硬塞入短暂提示。**新增功能必须把短群通知与可保留的私聊详情/历史记录分开**，或者提交明确的保留例外。新例外需在本文登记，不能偷偷修改计时规则。

### 3.2 恢复路径

新增功能至少提供适用的恢复路径：

- 超时：说明已超时，提供重新打开入口；失效按钮不得继续执行业务。
- 参数错误：保留当前步骤并提示合法格式，不要求用户从头输入已验证参数。
- 网络/API 错误：区分“业务未执行”和“业务已成功、消息未更新”；后者只重试显示。
- 涉及权益或复杂查询：提供历史/编号查询或私聊结果入口；数据库存在记录不能代替用户可访问的查询入口。
- 私聊业务：默认绑定 @setupode，在涉及积分或活动的页面显示目标群。
- 最终确认：展示参数、积分是否扣除、审批要求及发布目标，允许取消。

未实现的能力必须在功能文档中说明。数据库存在记录不能等同于用户可访问的查询功能。

### 3.3 清理可解释

新增限时反馈应告知可从哪里重新查询；需要理解删除时间的页面可注明“提示稍后自动清理，结果可在……查看”。避免每条短提示都重复长说明。不得用删除来隐藏错误、扣分、处罚依据或未完成操作。

## 4. 开发接入方法

### 4.1 群内普通反馈

优先使用 `Bot.send()`。默认成功提示随群配置清理；新功能失败提示应**显式**设置 120 秒，不能依赖中文关键词判断：

```python
bot.send(bot.group, '操作成功。')
bot.send(bot.group, '积分不足，未扣分。请获得足够积分后重试。',
         _delete_after=120 if bot.delete_after > 0 else 0)
```

`retention.notice_delay()` 是现有短通知的兼容兜底，按文案判断，且只对少于 700 字的消息应用失败时长。它不构成可靠的业务分类器。新增长错误、动态文案、国际化文案必须显式指定类别/时间。

普通直接 `Bot.call('sendMessage', ...)` 不经过 `Bot.send()` 的文案兜底；要么改用 `send()`，要么显式设置 `_delete_after`。不要绕过封装直接使用 `api.call()` 发送群消息。

### 4.2 活动、公告和交互卡片

```python
sent = bot.send(bot.group, card_text, keep=True, reply_markup=buttons)
# 业务完成并移除按钮后，普通结束提示：
bot.schedule_delete(bot.group, sent['message_id'])
# 需要阅读的失败/处罚结果：
bot.schedule_delete(bot.group, sent['message_id'],
                    seconds=120 if bot.delete_after > 0 else 0)
```

`keep=True` 表示这次发送不进入常规删除队列，**不意味着永远不会删除**。交互功能必须自己定义结束清理。

`editMessageText` 本身不会自动排队删除，也不会重置已有计时。编辑卡片后，必须显式决定保留或安排结束清理。

`_delete_after` 显式时长优先于 `keep=True`；持续保留消息不能同时传显式删除时长。

### 4.3 私聊填写步骤

```python
sent = bot.send(uid, '请输入入群验证时长（秒）。')
bot.track_private_step(uid, sent['message_id'], 'settings')
# 新步骤替换旧步骤时，track_private_step 自动安排旧提示 30 秒后清理。
# 最终预览和结果不登记为步骤。
bot.finish_private_steps(uid, 'settings')
bot.send(uid, final_preview)
```

- `private_steps` 只能记录**本机器人实际发出的提示消息 ID**，不能记录用户输入的 ID。
- `flow` 区分活动、设置、解封等流程，不能清掉另一流程的当前提示。
- 错误说明作为当前步骤附属提示时，可以 `replace=False` 追加跟踪；后续步骤完成再一起清理。
- 活动和群配置有超时清理；解封理由填写的当前提示不设置自动超时，到提交或取消才清理。
- 最终预览、提交结果、审批通知不登记为旧步骤，即使用户后来重新创建活动也保留。
- `allow_private=True` 仅用于明确跟踪的机器人旧提示。新增功能不得拿它删除用户私聊消息或整个聊天历史。

### 4.4 持久化和失败处理

删除任务存入各 Bot 的 SQLite `deletions` 表。单轮最多处理 50 条到期任务；队列在重启后继续执行。到期时间为执行目标，长轮询、网络请求或限流可能导致延迟。

- `400/403`：移除任务；可能已删除，也可能无权或无法删除，不能统一视为“删除成功”。
- `429`：按 Telegram `retry_after` 重试，至少等待 5 秒。
- 其他临时 API 错误：30 秒后重试。
- 总共最多 3 次尝试；放弃时记录 `delete_giveup` 审计。

`schedule_delete()` 用 `INSERT OR IGNORE` 去重，重复调用**不会延长已有任务**。确需改变到期时间时，必须显式更新所属聊天/消息的任务，并测试；不能假定再次排队会重置时间。

业务提交、消息发送/更新、删除排队应分别处理。后台重试不得重扣积分、重抽奖、重复警告或再次执行已经完成的业务。

## 6. 新增功能合入检查

每个新消息类型都必须在功能说明或变更描述中回答：

- [ ] 是成功、失败、处罚、交互、长期结果还是私聊步骤？
- [ ] 在哪个群/私聊发送，由哪个 Bot 实例管理？
- [ ] 明确保留多久，计时从发送、下一步、完成还是超时开始？
- [ ] 当前按钮在清理前是否仍有效？旧按钮如何失效？
- [ ] 超时/失败后，用户如何重开、取消、重试或查结果？
- [ ] 长文本和重要明细是否有可保留的详情或历史入口？
- [ ] 是否保留全部用户源消息、最终预览和实际处理结果？
- [ ] 重启、重复点击、更新失败是否会重复扣分、处罚或重复发分？
- [ ] 使用适当的自动化测试验证保留、到期、豁免、失败重试和跨群隔离？
- [ ] 若新增例外，是否明确获准并同步本文、帮助和功能文档？

相关实现：`retention.py`、`Bot.send/call/schedule_delete/sweep_deletions`、`private_steps`；测试见 `tests/test_retention.py` 及各功能测试。

### 邀请积分接入检查（2026-10-30）

邀请积分静默入账，不新增成功/失败通知、交互卡片或私聊步骤。新增展示仅在既有 `/points` 私聊查询内，由默认群的 Bot 实例提供，按现有规则保留，源消息保留；可随时重新查询。邀请去重记录与积分账本在同一事务提交，日上限、首次归属和零积分记录持久保存；重启或投递失败不重复加分。查询失败不会回滚或再次入账。该查询不提供逐条邀请历史。相关验证见 `tests/test_invites.py`，包含重复事件、事务失败、旧库迁移、跨群隔离及私聊结果不清理。无新增保留时长或例外。

### 空投下线（2026-10-30）

活动仅保留夺宝。空投表和填写数据彻底删除，旧按钮不再执行业务。用户源消息和既有群内消息不作批量删除。既有公告的删除队列继续按已登记时长执行，不对无删除任务的旧卡片追加批量清理。夺宝改为私聊命令启动交互填写，结果保留，其他私聊配置填写步骤的规则不变。新夺宝的过期回调使用 Telegram 按钮提示，不新增可清理消息。

### 私聊命令创建及邀请链接（2026-10-30）

`/invite` 专属链接及规则在私聊保留，可重发命令找回；领取失败不奖励积分，已保存链接复用。入群申请保存链接归属，真正入群后在积分事务内去重及限额；普通群内不新增奖励通知，`/points` 可查。AI 新闻播报代码和数据库表已移除，已有公告沿用删除队列。没有新增保留时长。

头像核验接口报错、响应不一致或无法核对资料头像时，签到回复“未加分、未计警告”的短失败提示，显式使用本群普通失败时长；用户签到消息保留，可重新 /checkin。发言检查失败仍静默不计分。

### 关键词积分、限时夺宝与 AI 问答下线（2026-11-04）

三个功能的命令、私聊填写流程、群内卡片、开奖公告、AI 回答及后台任务全部移除；`keyword_*`、`treasure*`、`ai_*`、`ai_media`、`chat_history` 表不再创建和使用，旧库中的存量表不读取也不删除。历史保留时长（夺宝 24 小时公告、关键词卡片 120 秒、AI 回答 600 秒）从时长表中移除。用户源消息和既有群内消息不作批量清理；仍在删除队列中的历史任务按已登记时长继续执行。拉黑后的消息删除改为仅依赖 Telegram `revoke_messages`，不再基于本地聊天记录补删；Jev 确认广告后不再清理聊天记录表。没有新增保留时长。

### 十连签到与五星播报接入检查（2026-10-30）

- 消息类别：群内十连签到结果、五星常驻/五星 UP 播报；均为普通成功提示，群内发送，默认群 Bot 实例管理。
- 保留时间：结果与播报各自按本群 `DELETE_AFTER_SECONDS` 默认 30 秒清理；用户签到源消息保留。没有新增保留时长或例外。
- 播报范围：一次签到按十连逐抽计分（三星 0、四星 1、五星常驻 5、五星 UP 10），单次最多 3 个四/五星；只有出现五星才另发播报，双黄/三黄合并，四星/三星不播报。
- 恢复和去重：签到结果和五星播报分别持久记录发送标记；结果发送成功但播报失败后，更新重试只补播报，不重复结果；同一签到事件重放不重复发分。保底计数、50/50 大保底标记和十连结果在签到事务内保存，重启继续累计；当天已签到或事务失败不产生新的十连结果。
- 数据：`checkin_pity` 保存跨天四星/五星保底计数及下次大保底标记，`checkin_draws` 保存十连结果、本次得分及发送标记。旧签到事件没有十连结果时按历史签到回放，不补抽；现用表结构重复启动安全，不提供缺少 `guaranteed` 字段的旧表兼容升级。
- 验证：`tests/test_points.py` 覆盖逐抽相加、单次最多 3 个四/五星、50/50 歪了后大保底、90 抽硬保底、四星/五星跨天累计、同日上限、结果重放、五星播报及播报失败后的单次补发。


私聊发送「签到」或 `/checkin`，核实当前群成员身份后，仅查询本人累计抽数、五星 UP／常驻次数、四星／五星保底进度及下次五星大保底状态。统计仅覆盖已保存的十连记录；不抽卡、不加分、不改变保底或当天签到状态。查询结果按现有私聊规则保留，用户源消息保留，可重复发送命令查询；实际签到仍在群内进行。
