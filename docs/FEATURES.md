# Setup 群管机器人功能说明

> 维护基线：2026-09-29。本文以当前代码为准；README 只作入口。

## 1. 部署与数据

- 运行目录：`/opt/tgbot`；服务：`tgbot.service`；进程用户：`tgbot`。
- 数据库：SQLite（默认 `bot.sqlite3`，线上为 `/var/lib/tgbot/bot.sqlite3`）。
- 关联群组：`@setupode`；关联频道：`@setup0de`。
- 管理群可以登记多个。新群由该群群主在群内发送 `/group_add [频道用户名或ID]` 登记，再私聊 `/groups` 启用并选择当前私聊操作群。
- 每个群有独立 SQLite 数据库，积分、名单、审核、警告、活动及 AI 记录互不共享。已启用群同时处理群内更新；私聊积分、排行榜和达标榜会让用户选择数据所属群，管理员的其他群级私聊操作仍使用 `/groups` 选择的当前群。
- 机器人须在每个启用群及其关联频道拥有管理员权限；群内需有删消息、限制成员和邀请用户权限。标签升级还需授予管理成员标签权限。
- 主要环境变量见 `.env.example`，包括 Telegram token、群/频道 ID、验证时长、禁言时长、群内命令限制、AI 地址/密钥/模型等。

## 2. 入群验证

1. 入群申请先检查黑名单和账号是否为 Bot。
2. 申请人必须关注 `@setup0de`，并在 4 分钟内完成随机算术题；最多答错 3 次。
3. 验证成功才批准入群；超时、失败或未关注会拒绝，用户可重新申请。
4. 通过普通邀请直接进入的成员会先被限制发言，再在群内完成验证；超时会移出。
5. 黑名单、机器人账号不能绕过验证；管理员、白名单成员和匿名管理员消息有相应豁免。

群内入群验证提示在验证期间保留；成功、失败或超时后按本群自动删除设置清理，重启后继续处理。

## 3. Jev 广告举报

1. 管理员或已完成验证的群员**回复目标消息发送 `/report`**，才调用 Jev；日常聊天不会自动提交。
2. 支持文字、媒体说明及文字链接。Jev 使用结构化广告/非广告分类；非广告直接反馈，不处罚。
3. 判为可疑广告后，群内显示原消息摘要、模型 ID、广告概率和确认按钮。原消息在确认前保留。
4. **1 名当前群管理员同意，或 5 名不同的当前群员同意**后，删除原消息并警告一次。每人一票；机器人、外群用户和未完成验证者不能投票。管理员可点击驳回。
5. 重复举报相同内容不会重复调用；编辑消息会使未完成的旧投票失效，需要重新回复 `/report`。消息即使重启或重试也最多记一次警告。
6. 待投票卡片最多保留 24 小时，结束后按本群自动删除设置清理。接口失败不处罚；最多自动重试三次，最终失败可重新提交。
7. 发送者为管理员、白名单、本机器人或关联频道时沿用豁免。警告累计 3 次沿用现有禁言、移出及黑名单规则。

配置：`JEV_API_KEY`、`JEV_MODEL=jev-latest`、`JEV_ENABLED=1`；群主可在 `/settings` 单独切换本群 Jev 举报功能。Jev 密钥与 `/ai` 密钥独立。举报不占签到等日常命令额度。

官方接口：[TypeSafe API](https://docs.typesafe.ai/api)。Jev 目前处理文字，不识别纯图片、语音或视频内容。

## 4. 管理员命令

命令可回复目标消息执行，也可填写数字用户 ID；`@用户名` 会先解析并重新校验成员 ID。

| 命令 | 作用 |
|---|---|
| `/warn [原因]` | 警告；累计第 3 次触发禁言、移出和黑名单 |
| `/mute [分钟]` / `/unmute` | 禁言或解除禁言；未指定时使用本群 `MUTE_SECONDS`（默认 1440 分钟） |
| `/warnings` / `/resetwarn` | 查看或清零警告（不自动解除黑名单） |
| `/ban [原因]` / `/unban` | 封禁或解除黑名单；封禁会禁言、踢出并删除目标消息 |
| `/white [ID] [备注]` / `/unwhite` / `/whitelist` | 管理白名单 |
| `/audit [ID]` | 查看最近的操作日志（支持按用户 ID 过滤） |
| `/status` `/help` | 查看运行状态和命令帮助 |
| `/airdrop 最低积分 [活跃分钟] [中奖人数] 奖品` | 申请或创建空投；默认 1 人，最多 20 人。普通成员每天可申请一次，由任一群管理员按钮同意后开奖；管理员每天可直接发起一次，超额需群主批准 |
| `/airdrops [编号]` | 查看当前管理群最近 20 条空投记录，或查询指定编号的完整记录；私聊时按当前激活群查询 |


## 5. 用户功能

- `/checkin`：每天一次，随机获得 1–5 积分；必须公开头像。成功、失败和重复签到都会删除用户源消息。
- 发言积分：公开头像成员每天最多获得 5 分；未公开头像静默不计分。签到时未公开头像会提示一次并计警告。
- `/points`：私聊查看个人积分；多群时先选群；群内不展示结果。
- `/rank`：私聊查看排行榜，每页 50 人、按钮翻页，不 @ 其他成员；多群时先选群；群内不展示结果。
- `/milestones`：私聊查看首次达到 `UPGRADE_POINTS`（默认 50）分的前 50 位成员，按首次达标顺序排列；多群时先选群，只显示排名和昵称，有自定义标签也会入榜，不 @ 成员。
- 中文文字别名仍可用：签到、积分、排行榜、原神榜；别名不带斜杠，也不会出现在 Telegram 命令菜单或 `/help` 中，显示的命令保持英文。
- `/bin <前缀>`：调用 BIN 查询接口返回卡组织、国家、银行等信息。
- `/ai <提示词>` 或回复消息发送 `/ai`：调用配置的模型，回答末尾标注服务返回的模型 ID（服务未返回时使用配置 ID）；普通成员每 60 秒一次（群聊与私聊共享），管理员与白名单不限频，群聊会带有限历史上下文。
- `/help`：查看全员、管理员和群主功能及自动规则。

签到、积分、排行榜的用户源消息会在处理并提示后删除（群内与私聊均适用），机器人的结果与警告提示保留。

## 6. 积分、标签与活动

- 积分达到 `UPGRADE_POINTS` 时可升级为 `UPGRADE_TAG`，已有自定义标签不覆盖。
- 普通成员可通过 `/airdrop 最低积分 [活跃分钟] [中奖人数] 奖品` 申请，每人每天一次；默认抽 1 人，最多抽 20 人；不设活跃要求但指定人数时，活跃分钟填 `0`。申请发送到对应群，由任一群管理员同意后立即开奖，或拒绝。开奖结果标注发起人与同意人，并 @ 发起人和所有中奖者。管理员每日可直接创建一次；超额仍需群主批准，群主可直接发起。仅「有积分记录、仍在群内、已完成入群验证、已设置成员标签或自定义头衔」的成员参与，不扣分；实际人数不足时按实际人数开奖。

## 7. 自动任务与限制

- 群内普通机器人消息按 `DELETE_AFTER_SECONDS` 自动删除，默认 30 秒；待审批卡片在处理前保留，空投开奖结果和达标祝贺消息长期保留。
- 普通成员群内机器人命令受 `GROUP_COMMAND_LIMIT` 限制（计数范围：`/help`、`/checkin`、`/points`、`/rank`、`/milestones`、`/bin`、`/ai`），超出后需私聊；管理员和白名单不受此限制。
- 机器人启动时跳过历史积压更新，避免重复处罚旧消息。

## 8. 部署验证

运行 `python3 -m unittest discover -s tests`。部署后核对服务状态、Jev 接口可用性及群权限；不使用真实群员进行处罚测试。

## 9. 已知边界

- Telegram Bot API 无法可靠枚举群内全部历史成员，因此 Bot 清理只处理已记录或命令明确指定的目标。
- 频道身份发送的消息无法按普通用户完全处理，第三次违规会限制该频道身份。

## 10. 多群管理

1. 将机器人加入新群并授予管理员权限；关联频道也需将机器人设为管理员。
2. 由目标群群主在群内发送 `/group_add`。如使用不同关联频道，可带参数，例如 `/group_add @channelname`。
3. 群主或已管理群的管理员私聊机器人发送 `/groups`，分别启用/停用管理群，并选定管理员私聊管理操作使用的“当前私聊管理群”。
4. 每个启用群同时运行功能；私聊 `/points`、`/rank`、`/milestones` 时会单独显示群组选择按钮，积分和榜单按所选群隔离。其他群级私聊操作沿用 `/groups` 选定的当前群。用户在多个群被拉黑时，可用 `/appeal 群ID 理由` 指定申请目标。
5. 主群沿用 `/var/lib/tgbot/bot.sqlite3`；其他群使用 `/var/lib/tgbot/groups/<群ID>/bot.sqlite3`，举报与投票分别保存在各群数据库中。群组登记表和轮询游标属于机器人控制数据。

登记命令只接受目标群群主操作。若启用群后来撤销机器人权限，服务启动时会单独停用该群，不影响其他群。

### 群主独立配置

- 群主私聊 `/settings`，通过群组选择按钮打开对应设置页。只有该群 Telegram 群主（`creator`）能查看或修改；每次点击都会重新核验群主身份。
- 数值和文本项点击后机器人发送普通消息提示，直接发送新值即可，无需引用回复或弹窗；Jev 举报开关直接点按钮切换；存在自定义值时可点“恢复默认”。签到积分范围一次输入，例如 `5-10`，避免下限和上限分两次修改导致非法区间。发送 `/cancel` 可取消等待中的修改。
- 配置保存在对应群自己的 SQLite 数据库，重启后仍生效；群组之间互相隔离。
- 可配置积分范围、发言积分及日上限、禁言/验证时长、群内命令上限、消息自动删除、AI 历史上下文、AI 冷却、Jev 举报开关、达标积分和标签。
- 验证时长限制 30–300 秒，成员标签符合 Telegram 16 个 UTF-16 字符且不能含 Emoji 的要求；签到下限不得高于上限。签到仍保持每天一次。
- “入群验证频道”按钮允许为该群单独设置 `@频道用户名` 或频道数字 ID；机器人必须是该频道管理员。“频道邀请链接”按钮可设置对应的 `https://t.me/...` 公开链接或私有邀请链接。验证按钮使用本群保存的链接，频道成员资格检查仍使用本群绑定的频道 ID。也可在登记新群时通过 `/group_add @频道用户名` 指定频道。
- AI API 密钥、API 地址、机器人令牌和数据库路径属于服务凭据或部署配置，不向群主设置开放；AI 模型 ID 固定使用部署配置，不提供群内修改入口。


## 私聊解封申请（2026-09-21）

群主收到的申请和待处理申请列表显示申请人昵称（可点击提及）、@用户名及数字 ID；未设置用户名时仍可通过昵称提及申请人。

被拉黑的用户私聊机器人发送 `/appeal 理由`；也可先发 `/appeal`，再发一条文字理由（最多 1000 字），`/cancel` 取消填写。发送 `/start` 会显示申请入口。

申请持久保存后通知当前群主，群主点击「批准解封」或「拒绝申请」。只有当前群主有处理权限；群主私聊 `/appeals` 可查看最早的 20 条待审申请，处理后再次查看下一批。群主需要先私聊启动机器人，才能接收私信；通知失败每 5 分钟重试。

待审期间不可重复提交，每人 24 小时最多提交一次。批准后解除 Telegram 封禁及本地黑名单、清零警告，私聊通知用户重新申请入群并完成验证。拒绝不会解除封禁，结果会私聊反馈。封禁记录发生变化时旧申请失效；Telegram 解封失败则保留待审状态供群主重试。历史消息和积分不会恢复。


## 积分达标恭喜消息（2026-09-21）

达到 50 分（配置 `UPGRADE_POINTS`）时，在群内发送「第 N 位累计积分达到 50 分」的恭喜消息。达标通知独立于成员标签：已有自定义标签、管理员身份或没有标签管理权限都不妨碍发送；积分标签升级仍独立运行。

每位用户每个门槛仅登记一次序号，保存到 SQLite，重启、积分清零后再次达标不会重复编号。发送失败按一分钟间隔重试；定期检查并补发遗漏通知。恭喜消息保留在群内，不参与自动删除。黑名单、已离群成员不发送。历史补发优先使用已保存的升级时间排序；没有历史时间的记录按补录顺序编号。


## 操作日志（2026-09-22）

管理员在群内发送 `/audit`，查看最近 100 条全部操作日志（即使回复消息也不自动筛选）。发送 `/audit 数字ID` 或 `/audit @用户名`，查看该用户作为操作者或目标的最近 20 条日志。按时间、日志编号倒序排列，长结果自动分条发送；无效目标会提示错误。

AI 上下文规则：回复消息调用时，结合过滤后的近期群聊理解引用消息，优先回答当前问题与引用内容；普通群内提问使用触发消息之前的近期成员发言，过滤命令、积分别名和机器人通知。空 `/ai` 需补充问题或引用消息。

AI 引用会优先沿已保存的消息回复关系还原对话链，再参考近期群聊。AI 回答记录关联原问题，群聊背景标注消息 ID 与回复目标；论坛话题按话题隔离。旧记录缺少回复关系、记录已过期或未收录时会明确标注缺失，不推测历史。

AI 图片分析：回复照片或 JPG/PNG/WebP 图片文件发送 `/ai`（可附问题），也支持图片说明中的 `/ai 问题`。同一相册的已记录图片会按顺序一起发送，最多 10 张、单张 10 MB、合计 20 MB；相册索引保留 24 小时，不保存图片内容。旧相册未收录的图片无法补回，可重新发送；引用中仍附带的单张图片可直接读取。图片下载失败会提示，不会退回只解释标题。
