# 功能与命令

核对日期：2026-11-05。本文是功能规则的唯一位置：验证流程、命令与按钮、权限、失败恢复与限制。配置项和部署步骤见[配置与部署](DEPLOYMENT.md)；消息保留规则见 [AGENTS.md 第 3.1 节](../AGENTS.md)。

当前版本只实现入群验证和两个工具查询：没有其他命令、表或按钮入口，也不接受 `/checkin`、`/points`、`/manage` 之类的旧命令。

## 1. 默认群与身份

只处理 `GROUP_ID` 配置的群和用户私聊。其他群的消息、入群申请、成员更新和按钮回调直接忽略，不写入数据库。

群主是 Telegram 的 `creator`，管理员是 `administrator`。放行和拒绝都重新向 Telegram 核实身份，不使用缓存或按钮数据里的声明。

## 2. 入群验证

### 2.1 申请入群（推荐路径）

1. 用户提交入群申请，机器人在其私聊发送验证卡片：一句提示、`① 关注频道` 按钮和 4 个答案按钮。
2. 用户先关注关联频道，再点击 `a + b` 的正确答案。
3. 通过后机器人调用 `approveChatJoinRequest` 批准入群，卡片改为“✅ 已通过频道关注与人机验证。”。

判定顺序是**先查频道关注，再判答案**：未关注时点击任何答案只提示“尚未检测到关注频道”，不消耗答错次数，也不通过验证。频道状态为 `creator`、`administrator`、`member`，或 `restricted` 且仍是成员时，视为已关注。

### 2.2 直接进群（无审批的邀请链接）

1. 普通成员进群后立即被禁言（撤销全部发言权限）。
2. 机器人在群内发送同样的验证卡片，通过后按本群默认权限恢复发言。
3. 超时或答错 3 次会被移出群；他可以重新申请或重新进群，重新验证。

### 2.3 次数与时间

- 验证有效期 `VERIFY_SECONDS`（默认 240 秒，可配置 30–300 秒）；超时后申请被拒绝，已进群成员被移出。
- 最多答错 3 次；第 3 次答错立即拒绝并清除记录。
- 只有被验证人本人能点击答案按钮；其他人点击只会收到“这是其他成员的验证”提示，不消耗次数。
- 旧卡片、旧随机串或已超时的按钮一律提示“这条验证已失效”，不会通过验证。
- 重复的入群或申请更新沿用同一道题，不会重复发卡片，也不会重复禁言。

### 2.4 放行与拒绝

| 情况 | 处理 |
|---|---|
| 群主、管理员 | 直接放行，不发题、不禁言 |
| Bot | 只有群主或管理员邀请才放行；其他情况立即封禁 |
| 机器人自己 | 忽略 |
| 已验证成员 24 小时内重新入群 | 不再重复验证（保留通过状态一天） |
| 成员离开群 | 取消未完成的验证；已通过的记录保留到过期 |

本版本没有黑名单、警告或禁言记录：管理员在 Telegram 里手动操作群成员即可。

## 3. 命令

| 命令 | 推荐位置 | 用途 |
|---|---|---|
| `/start` | 私聊 | 说明机器人用途和入群验证流程 |
| `/help` | 群、私聊 | 查看入群验证步骤、限制和可用命令 |
| `/rate [金额] <原币> <目标币>` | 群、私聊 | 汇率换算，例如 `/rate 100 USD CNY` 或 `/rate USD CNY` |
| `/bin <6–8 位数字>` | 群、私聊 | 卡 BIN 查询，例如 `/bin 45717360` |

- 支持 `/help@机器人用户名` 形式；指向其他机器人的命令一律静默忽略（群、私聊都是）。
- 未知命令在群内和私聊提示“尚未提供这个命令，发送 /help 查看可用功能。”；私聊的纯文字消息不回应，避免被外部用户刷接口配额。
- 没有中文斜杠命令或中文文字别名，也没有配置命令。
- 管理员和群主没有额外命令；放行由入群事件自动处理。
- 未完成验证的成员在群内不能使用 `/rate`、`/bin`（与所有群内业务一致）；私聊不受限。

### 3.1 汇率换算 /rate

`/rate 100 USD CNY`（金额、原币、目标币）或 `/rate USD CNY`（金额默认 1）。金额最多 15 位整数、8 位小数，不接受负数与科学计数。币种以接口返回列表为准（含 BTC 与贵金属），支持小写输入；USDT 是独立币种，不自动当作 USD。回复显示换算结果、单位汇率和数据时间；数据来自 exchangerate.fun（每小时更新），本机以 USD 基准缓存 1 小时，接口失败不使用过期缓存，也不伪造结果。

### 3.2 卡 BIN 查询 /bin

`/bin 45717360`（6–8 位数字）。数据来自 cardbincheck.com（IPNOVA），回复卡组织、类型（信用卡/借记卡/预付卡/签账卡）、卡种、发卡行、国家/地区，以及发卡行网址和电话（缺失显示“未知”）。部署配置 `BIN_API_KEY` 时按额度计费并携带密钥请求；未配置时上游按 IP 限流开放。成功结果缓存 24 小时；上游 404 提示“未收录”、429 提示“上游限流”、网络失败提示“暂时不可用”，密钥无效时提示检查配置。

两个查询在命令处理线程内同步执行，超时 10 秒；等待期间其他更新排队，属于已知限制。

## 4. 按钮

| 位置 | 按钮 | 行为 |
|---|---|---|
| 验证卡片 | `① 关注频道` | 打开配置的关联频道链接（未配置时不显示） |
| 验证卡片 | 4 个数字选项 | 选择算术题答案；答对且已关注频道即通过验证 |

按钮回调格式为 `v:{用户ID}:{随机串}:{答案}`。服务器端重新校验：点击人是否为目标用户、随机串是否匹配当前题目、验证是否仍在有效期、频道关注是否成立。旧卡片、旧随机串或过期验证统一提示“这条验证已失效”，不重复执行业务。

## 5. 权限与前置条件

- 机器人必须是群和验证频道的管理员：频道用于读取关注状态，群内需要限制成员、邀请成员和撤回消息（`can_restrict_members`、`can_invite_users`、`can_delete_messages`）。缺少权限时启动即报错退出。
- 群应开启“入群申请”，此时验证在私聊完成；未开启时成员直接进群，由机器人先禁言再在群内验证。
- 群主与管理员不受验证约束；Bot 只接受管理员或群主邀请。

## 6. 失败与恢复

| 情况 | 行为 |
|---|---|
| 验证卡片发送失败（网络/限流） | 最多重试 3 次（间隔 30 秒）；仍失败则拒绝申请或移出成员 |
| 批准入群暂时失败（网络/限流/权限） | 保留通过状态，后台每 30 秒重试批准，最多 5 次；期间提示“正在提交入群申请” |
| 批准入群持续失败 | 停止重试并写 `verification_approve_gaveup` 审计；申请仍在 Telegram 侧挂起，需人工批准或撤销 |
| 入群申请已撤销/过期/用户已注销 | 清除本地记录并写 `verification_approve_expired` 审计，提示重新申请 |
| 无法禁言直接进群的成员 | 写 `verification_restrict_failed` 审计并把该成员移出，不允许未验证成员留在群里 |
| 私聊无法发起（用户未与机器人互动） | 直接拒绝申请并记录审计 |
| 拒绝申请或移出成员时权限不足 | 保留记录并标记失效，每 30 秒重试，最多 10 次；仍未成功则写 `verification_conclusion_gaveup` 审计并停止重试 |
| 申请已过期或被撤销 | 清除本地记录，提示用户重新申请 |
| 恢复发言权限失败 | 保留通过状态并每 30 秒重试，最多 5 次；仍未成功则写 `verification_restore_gaveup` 审计，并在群里提醒管理员手动解除限制 |

Telegram 调用与 SQLite 不构成同一事务：状态以数据库为准，外部调用失败保存为可重试状态；审计表记录 `verified`、`verification_timeout`、`verification_attempts`、`verification_delivery_failed`、`verification_restrict_failed`、`verification_approve_expired`、`verification_approve_gaveup`、`verification_restore_gaveup`、`verification_conclusion_gaveup`、`reject_bot`、`allow_invited_bot`、`update_failed` 等动作。

## 7. 限制

- Bot API 无法枚举全部历史成员，也无法读取成员何时关注频道之外的平台信息；验证只依据 `getChatMember` 的当前状态。
- 群未开启“入群申请”时，所有正常邀请都会走“先禁言再群内验证”的路径。
- 机器人不能阻止管理员手动把未验证用户设为管理员；成为管理员后不再受验证约束。
- 管理员手动删除群内验证卡片等于放弃这次验证：成员此时被禁言，无法在群里求助，超时后会被移出，可重新进群重新验证。
- 后台维护受长轮询影响：有验证在途时轮询间隔为 1 秒，空闲时为 20 秒，超时结束和批准重试通常在到期后数秒内完成。
