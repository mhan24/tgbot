# 功能与交互规则

核对日期：2026-11-04。本文依据仓库代码；所有参数只来自部署环境变量，机器人内不提供配置命令。命令和权限见 [COMMANDS.md](COMMANDS.md)。

当前版本只实现入群验证：没有其他命令、表或按钮入口，也不接受 `/checkin`、`/points`、`/manage` 之类的旧命令。

## 1. 默认群与身份

只处理 `GROUP_ID` 配置的群和用户私聊。其他群的消息、入群申请、成员更新和按钮回调直接忽略，不写入数据库。

群主是 Telegram 的 `creator`，管理员是 `administrator`。放行和拒绝都重新向 Telegram 核实身份，不使用缓存或按钮数据里的声明。

## 2. 入群验证

### 2.1 申请入群（推荐路径）

1. 用户提交入群申请，机器人在其私聊发送验证卡片：一句提示、`① 关注频道` 按钮和 4 个答案按钮。
2. 用户先关注关联频道，再点击 `a + b` 的正确答案。
3. 通过后机器人调用 `approveChatJoinRequest` 批准入群，卡片改为“✅ 已通过频道关注与人机验证。”。

判定顺序是**先查频道关注，再判答案**：未关注时点击任何答案只提示“尚未检测到关注频道”，不消耗答错次数，也不通过验证。频道状态为 `creator`、`administrator`、`member`，或 `restricted` 且仍是成员时，视为已关注。

### 2.2 直接进群（无审批的邀请链接）

1. 普通成员进群后立即被禁言（撤销全部发言权限）。
2. 机器人在群内发送同样的验证卡片，通过后按本群默认权限恢复发言。
3. 超时或答错 3 次会被移出群；他可以重新申请或重新进群，重新验证。

### 2.3 次数与时间

- 验证有效期 `VERIFY_SECONDS`（默认 240 秒，可配置 30–300 秒）；超时后申请被拒绝，已进群成员被移出。
- 最多答错 3 次；第 3 次答错立即拒绝并清除记录。
- 只有被验证人本人能点击答案按钮；其他人点击只会收到“这是其他成员的验证”提示，不消耗次数。
- 旧卡片、旧随机串或已超时的按钮一律提示“这条验证已失效”，不会通过验证。
- 重复的入群或申请更新沿用同一道题，不会重复发卡片，也不会重复禁言。

### 2.4 放行与拒绝

| 情况 | 处理 |
|---|---|
| 群主、管理员 | 直接放行，不发题、不禁言 |
| Bot | 只有群主或管理员邀请才放行；其他情况立即封禁 |
| 机器人自己 | 忽略 |
| 已验证成员 24 小时内重新入群 | 不再重复验证（保留通过状态一天） |
| 成员离开群 | 取消未完成的验证；已通过的记录保留到过期 |

本版本没有黑名单、警告或禁言记录：管理员在 Telegram 里手动操作群成员即可。

## 3. 消息保留

- 群内机器人消息默认 30 秒清理，可用 `DELETE_AFTER_SECONDS` 调整，设为 0 关闭。
- 验证卡片在验证期间保留（`keep=True`），通过、答错上限、超时或记录失效后转入普通清理队列。
- 用户命令、私聊来信和验证卡片本身不做删除，只有机器人发出的群消息和已结束的卡片进入清理队列。
- 其他 Bot 发到本群的可见消息按群常规时长清理；频道身份发言不清理也不处理。
- 私聊消息不自动删除。
- 群内失败提示（例如未知命令）显式使用 120 秒（`Bot.notice_seconds()`），不按文案关键词猜类别；验证过程中的提示通过按钮弹窗回答，不额外发群消息。

详细规则见 [消息保留规范](MESSAGE_RETENTION.md)。

## 4. 命令

当前只有两个全员命令：`/start`（私聊）和 `/help`（群、私聊）。参数均不可用；未知命令提示发送 `/help`，该提示按失败时长保留并在群内自动清理。中文别名、管理员命令和配置命令都不存在。

## 5. 失败与恢复

| 情况 | 行为 |
|---|---|
| 验证卡片发送失败（网络/限流） | 最多重试 3 次（间隔 30 秒）；仍失败则拒绝申请或保留禁言状态 |
| 私聊无法发起（用户未与机器人互动） | 直接拒绝申请并记录审计 |
| 拒绝申请或移出成员时权限不足 | 保留记录，每 30 秒重试；权限恢复后继续 |
| 申请已过期或被撤销 | 清除本地记录，提示用户重新申请 |
| 恢复发言权限失败 | 保留通过状态并每 30 秒重试，最多 5 次；仍未成功则停止重试并写 `verification_restore_gaveup` 审计，成员需人工解除限制 |
| 禁言失败（无法限制新成员） | 不发验证卡片，记录 `verification_restrict_failed` 审计 |

Telegram 调用与 SQLite 不构成同一事务：状态以数据库为准，外部调用失败保存为可重试状态；审计表记录 `verified`、`verification_timeout`、`verification_attempts`、`verification_delivery_failed`、`verification_restrict_failed`、`verification_approve_failed`、`verification_restore_gaveup`、`reject_bot`、`allow_invited_bot`、`delete_giveup`、`update_failed` 等动作。

## 6. 限制

- Bot API 无法枚举全部历史成员，也无法读取成员何时关注频道之外的平台信息；验证只依据 `getChatMember` 的当前状态。
- 必须把机器人设为群和频道的管理员：频道里要能读成员状态，群里要能删消息、限制成员、邀请成员。
- 群未开启“入群申请”时，所有正常邀请都会走“先禁言再群内验证”的路径。
- 机器人不能阻止管理员手动把未验证用户设为管理员；成为管理员后不再受验证约束。
