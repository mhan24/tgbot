# Setup Telegram 群管机器人


> 完整、按当前代码维护的功能说明见 [`docs/FEATURES.md`](docs/FEATURES.md)。其中列出了 Jev 举报流程和运行边界。

机器人可同时启用多个管理群。群主将机器人设为管理员后，在新群发送 `/group_add`；再私聊机器人发送 `/groups` 启用该群。每群使用独立 SQLite 文件保存积分、名单、警告、审核、活动和 AI 记录。私聊 `/points`、`/rank` 或 `/milestones` 时，如果有多个已启用群，会先让用户选择要查看的群组。

Python 3.9+，仅使用标准库；SQLite 持久化，systemd 守护运行。

## 行为

- 机器人账号不予放行，普通用户通过频道关注和人机验证后入群。
- 已开启入群申请的群：机器人私聊申请人，要求先关注关联频道，再完成随机算术选择题。验证期限 4 分钟，最多答错 3 次；通过后批准，超时/失败拒绝，可重新申请。
- 通过其他邀请途径直接进群：立即限制发言，群内验证；超时移除，可重新申请。Bot API 无法替代群主控制所有邀请途径，建议保持“批准新成员”开启并只分发需要审核的邀请链接。
- 回复消息发送 `/report`，Jev 判为可疑广告后经群内投票确认才删消息并警告。警告累计到第 3 次，禁言 24 小时并移出本群、加入黑名单；次数不自动归零，可由管理员清除（`/resetwarn` 不解除黑名单，需 `/unban`）。后续违规会重新触发禁言。
- 管理员、群匿名管理员消息、关联频道发言豁免。其他频道身份广告同样累计 3 次，第三次禁止该频道发言（Telegram 对频道身份只能封禁，需管理员在群设置解除）。
- Jev 举报为人工提交与投票确认流程；目前不做图片 OCR、二维码或视频内容识别。
- 首次启动跳过启动前积压更新，避免追罚历史消息；历史未处理申请需要重新申请。之后通过数据库保存处理位置。

## 管理员命令

回复成员消息执行（或命令后填写数字用户 ID）：

| 命令 | 用途 |
| --- | --- |
| `/warn [原因]` | 警告，累计第 3 次禁言并移出本群、加入黑名单 |
| `/mute [分钟]` | 禁言，默认使用本群 `MUTE_SECONDS` 设置值（默认 1440 分钟），例如 `/mute 60` |
| `/unmute` | 解除禁言；尚未通过入群验证者不能跳过验证 |
| `/warnings` | 查看警告数 |
| `/resetwarn` | 清零警告，不解除现有禁言，也不解除黑名单 |
| `/ban [原因]` | 移出本群并加入黑名单，阻止再次加入 |
| `/unban` | 解除黑名单，可重新申请入群 |
| `/white [ID] [备注]` | 加入白名单，豁免广告检测、群内次数、三日自动黑名单、AI 冷却与验证 |
| `/unwhite [ID]` | 移出白名单，恢复正常限制 |
| `/whitelist` | 查看白名单（黑名单优先于白名单） |
| `/audit` / `/audit ID` | 不指定 ID 查看最近 100 条全部日志；填写 ID 查看该用户最近 20 条日志 |
| `/status` | 查看运行状态 |
| `/help` | 查看完整功能帮助 |

使用 ID 示例：`/mute 123456789 60`。匿名管理员需切换为个人身份。管理员和本机器人不能被命令处罚。

## 功能菜单

群内或私聊机器人发送 `/help`（支持 `/help@机器人名`），返回当前功能清单，并区分「全员可用」「仅管理员」「仅群主」和自动规则。任何成员均可查看，不校验管理员身份。

## Jev 广告举报

1. 管理员或已完成验证的群员**回复目标消息发送 `/report`**，才调用 Jev；日常聊天不会自动提交。
2. 支持文字、媒体说明及文字链接。Jev 使用结构化广告/非广告分类；非广告直接反馈，不处罚。
3. 判为可疑广告后，群内显示原消息摘要、模型 ID、广告概率和确认按钮。原消息在确认前保留。
4. **1 名当前群管理员同意，或 5 名不同的当前群员同意**后，删除原消息并警告一次。每人一票；机器人、外群用户和未完成验证者不能投票。管理员可点击驳回。
5. 重复举报相同内容不会重复调用；编辑消息会使未完成的旧投票失效，需要重新回复 `/report`。消息即使重启或重试也最多记一次警告。
6. 待投票卡片最多保留 24 小时，结束后按本群自动删除设置清理。接口失败不处罚；最多自动重试三次，最终失败可重新提交。
7. 发送者为管理员、白名单、本机器人或关联频道时沿用豁免。警告累计 3 次沿用现有禁言、移出及黑名单规则。

配置：`JEV_API_KEY`、`JEV_MODEL=jev-latest`、`JEV_ENABLED=1`；群主可在 `/settings` 单独切换本群 Jev 举报功能。Jev 密钥与 `/ai` 密钥独立。举报不占签到等日常命令额度。

官方接口：[TypeSafe API](https://docs.typesafe.ai/api)。Jev 目前处理文字，不识别纯图片、语音或视频内容。

## 白名单

受信任的成员可用 `/white [ID/@用户名] [备注]` 加入白名单，`/unwhite` 移除，`/whitelist` 查看。仅管理员可操作，白名单成员享有以下豁免：

- 不参与广告规则检测：疑似广告消息不删除、不累计警告
- 不受每日群内操作次数限制（可无限使用签到、积分、排行榜、BIN、AI 问答等）
- 不被判定为「连续 3 天只签到未发言」，不会被三日自动规则拉黑或清空积分
- 不受 AI 每分钟 1 次冷却，且无需完成入群验证

**黑名单优先**：同一用户同时在两张名单时按黑名单处理（封禁、拒绝入群、继续检测广告）；被拉黑的人无法加入白名单，需先 `/unban`。白名单成员若账号被盗，其消息不会被广告规则拦截，因此只应加入完全可信的人。管理员本身已天然享有上述大部分豁免，无需重复加入。

## 黑名单

警告累计到第 3 次会禁言并移出本群、加入黑名单；管理员也可用 `/ban` 直接移出并拉黑。黑名单用户无法通过入群申请加入（申请被直接拒绝），若经邀请链接进群会被立即再次移除。禁令通过 Telegram `banChatMember` 与本地 `blacklist` 表共同维持，重启保留。管理员和本机器人不能被拉黑。`/unban` 解除黑名单并允许重新申请入群；`/resetwarn` 只清零警告次数，不解除黑名单。`/status` 会显示当前黑名单人数。

## 配置与部署

复制 `.env.example` 为 `.env`，填写 token。配置文件权限 `600`；不要提交密钥。

群主可私聊机器人发送 `/settings`，通过群组选择按钮进入设置页，再点选项目修改；数值项按提示回复，开关项点按切换，已覆盖的项目可用“恢复默认”按钮还原。设置写入各自群组的 SQLite 数据库，重启后保留。每个群可单独绑定入群验证频道和频道邀请链接，修改后该群的新成员验证会使用自己的链接。机器人令牌、AI API 密钥、API 地址和数据库路径仍由部署环境管理。

服务器目录 `/opt/tgbot`，服务名 `tgbot.service`，SQLite 位于 `/var/lib/tgbot/bot.sqlite3`。远端环境文件只包含机器人配置，不复制 SSH 密码。服务以专用 `tgbot` 用户运行，开机启动、故障自动重启。

```sh
python3 -m unittest discover -s tests -v
systemctl status tgbot
journalctl -u tgbot -n 50 --no-pager
systemctl restart tgbot
```

修改 `.env` 部署默认值后需重启服务；群主在 `/settings` 按钮页修改的群组覆盖值会立即生效、无需重启。入群验证可设 30–300 秒，符合 Telegram 入群申请私聊最长 5 分钟的限制。

部署验证包括真实 API 身份与权限核验、服务器长轮询、单元测试。不使用真实成员做处罚实验。

API 依据：https://core.telegram.org/bots/api#chatjoinrequest

## BIN 查询

任何成员可在管理群或机器人私聊发送 `/bin 45717360`，也支持 `/bin@setupqaqbot 45717360`。接受 6–8 位数字，调用 `https://lookup.binlist.net/{BIN}` 并发送 `Accept-Version: 3` 请求头。

返回卡组织、卡类型、品牌、是否预付卡、国家、币种、银行与卡号格式。缺失字段显示“未知”。成功结果缓存 24 小时；404、429、超时均有明确提示，限流期间暂停外部查询、已有缓存仍可使用。Binlist 数据和查询额度受上游服务限制，8 位 BIN 未必可查。

## 积分系统

仅管理群内使用，普通成员和以个人身份发言的管理员均可参加：

- `/checkin`：每日一次，随机获得配置范围内的积分（默认 1–5）。
- `/points`：累计积分、今日签到、今日发言积分和总榜排名；**仅私聊展示**，多群时先选择群组；群内触发只返回私聊跳转按钮。
- `/rank`：**仅私聊展示**完整排行榜（每页 50 人，按钮翻页，不 @ 其他成员），多群时先选择群组并核验在群身份；群内触发只返回私聊跳转按钮。
- `/milestones`：**仅私聊展示**首次达到积分门槛的前 50 位；多群时先选择群组；按首次达标顺序排列，只显示排名和昵称，不要求拥有「家人」标签，也不 @ 成员。
- 上述中文文字别名继续可用（签到、积分、排行榜、原神榜）；中文别名不带斜杠，Telegram 命令菜单与 `/help` 只显示英文命令。
- 每条新发言（文字或媒体）默认 1 分，每天最多 5 分。群主可单独调整每群的发言积分和每日上限。北京时间 00:00 重置每日额度，累计积分不清零。
- 命令、机器人、匿名频道身份、系统入退群通知、编辑消息不计分。未完成入群验证不能签到。
- 数据存入原 SQLite 的 `point_users` 和 `point_events` 表，重启保留；消息重复投递不会重复加分。
- 连续 3 个完整自然日只签到不发言会被清空积分并拉黑，详见「签到消息删除与异常签到处理」。
- 排行榜按累计积分统计所有有积分记录的用户，包含已退群的历史参与者。上线前已处理的聊天记录不补积分。

## 签到消息删除与异常签到处理

签到和积分查询命令处理后删除源消息。连续三个完整北京时间自然日每天签到、期间没有正常发言的成员，将被移出群并加入黑名单，积分清零。管理员及白名单豁免；部署当天、存在数据缺口的窗口不参与判定。

用户可私聊 `/appeal 理由` 申请解封，群主审核；管理员也可使用 `/unban ID` 解封。

## 群内操作次数限制

普通成员**每天在群内最多执行 3 次机器人操作**（`GROUP_COMMAND_LIMIT` 可调整，群主可按群覆盖，按北京时间 0 点重置）。计次范围是本机器人在群内的所有操作：`/help`、`/checkin`、`/points`、`/rank`、`/milestones`、`/bin`、AI 问答（`/ai`）。

达到上限后再在群内操作，机器人不再执行，并提示改用私聊（提示只在当天首次越限时发一次，避免刷屏；之后保持静默不再监听）。管理员与群主不受次数限制。私聊、以及回复按钮的回调不计入也不受限制。

## 群聊上下文

为了让 AI 能理解指代（「这个」「上面说的」），机器人会滚动记录已启用管理群内的消息：普通成员文字与媒体说明、以及机器人自己发出的消息（含开奖、警告、AI 回答等）。每个群单独保存上下文，私聊与未管理群不记录；投票确认的广告从上下文中移除。

记录只保留最近部分（默认每群 `HISTORY_MESSAGES=50` 条、最多 24 小时），定期清理，旧消息持续淘汰。触发 AI 时取最近约 6 小时内最多 `HISTORY_CONTEXT=50` 条、累计不超过 6000 字的记录附在提示词中，按时间从早到晚排列，并以 `<chat>` 标记为资料而非指令；数据量与字数上限保证提示词不会被刷爆。群主可按群调整保留条数与上下文条数。上游模型最多看到这些记录，超出范围的更早对话无法追溯。

## 消息自动删除

机器人在已启用群里发出的每条普通消息默认在 30 秒后自动删除（`DELETE_AFTER_SECONDS` 可调整，设为 0 关闭）；空投开奖结果和达标祝贺会保留在群内。其他机器人发到群里的消息也会一并删除。私聊消息和关联频道内容不受影响。

仍需等待用户或管理员操作的互动消息会保留，避免按钮在流程结束前失效：入群验证的答题消息（验证限时 4 分钟）、待审批的空投申请，以及群员投票中的 Jev 举报消息。验证成功、失败或超时后，验证提示按该群自动删除设置计时清理（默认 30 秒），重启后继续处理。完成操作后，审核卡片和空投审批卡片开始删除计时；空投开奖结果保留，Jev 举报结果按普通消息的设置自动删除。

删除时间由主循环驱动：有待删消息时机器人会改用 1 秒短轮询，因此实际删除时间接近设定值。删除失败会重试，最多 3 次后放弃并记入审计（例如消息已被其他管理员删除、或机器人权限不足）。

**平台限制**：Telegram 直到 Bot API 10.0 才允许机器人“看到部分由其他机器人发送的群消息”，所以只有机器人实际收到的那部分其他 bot 消息能被删除，无法保证覆盖全部。

**频道身份发言不会被删除**：以频道身份发言时，Telegram 可能同时提供 `sender_chat` 和 `from`。代码以 `sender_chat` 识别频道身份，避免把频道帖子误判为机器人消息。

## 标签升级

成员在群内累计积分达到本群门槛（默认 `UPGRADE_POINTS=50`）时，机器人调用 `setChatMemberTag` 设置标签（默认 `UPGRADE_TAG=家人`）。群主可分别调整各群的门槛和标签。仅对普通成员（含被限制但仍在群内的成员）生效；群主和管理员使用自定义头衔，不做标签处理。**如果该成员已有自定义标签，则保持原样不覆盖**，并记录原因避免反复请求。

标签设置成功后，机器人在群内发一条祝贺并 @ 该成员。祝贺消息发送失败只记录日志，不影响标签本身，也不会重复补发。

每个成员只处理一次，结果记录在 `upgrades` 表，重启保留；处理时机为签到或发言加分后立即检查。`setChatMemberTag` 要求机器人拥有 `can_manage_tags` 管理员权限：启动时若检测到缺失，会在日志中告警并在 `/status` 中显示“已停用”，此时不写记录，等待补授权限后自然生效。同一次调用失败（网络或权限错误）不会留下记录，下次加分时重试。

### 积分头像条件

签到和发言加分前实时调用 `getUserProfilePhotos`。头像不可见时静默不加分；发起签到另计1次警告，同一条消息不重复记警告。沿用累计3次警告禁言24小时规则，头像不可见时签到会在群内发送警告次数及公开头像的提示，达到阈值时提示禁言。普通发言没有头像只不加分，不记警告。

接口失败或响应异常时静默跳过加分，也不记警告。失败签到不占用当日签到次数；公开头像后可重新签到。Telegram Bot API 无法读取完整隐私设置，实际检查的是“头像对机器人可见”，不能证明对所有人公开。

## 积分门槛空投

任何群成员都可在群里或私聊机器人发送：`/airdrop 10 一份神秘礼品`。普通成员每天可申请一次；申请会发到对应群，由任一群管理员点“同意并开奖”后立即执行，或点“拒绝”。申请与开奖结果会显示发起人和同意人；重复提交或同日再次申请会被拦截。每名管理员每天仍可直接发起 1 次；超过后需群主批准，群主可直接发起。

发送 `/airdrops` 查看当前管理群最近 20 条开奖记录；发送 `/airdrops 23` 查看编号 23 的完整记录，包括状态、发起人、同意人、奖品、中奖者和区块证明。多群私聊查询按当前激活群检索。

命令格式：`/airdrop 最低积分 [活跃分钟] [中奖人数] 奖品`。默认中奖 1 人，中奖人数最多 20 人；要指定中奖人数但不限制活跃度时，将活跃分钟写为 `0`。例如 `/airdrop 50 840 5 奖品` 表示最低 50 分、840 分钟内发过言、抽 5 人；`/airdrop 50 0 5 奖品` 表示不限制活跃时间、抽 5 人。立即从积分数据库记录的用户中，按区块哈希顺序抽取最多指定人数；每位中奖者均须达到积分门槛、仍在群里、已完成入群验证，且**已设置成员标签（tag）或自定义头衔（custom_title）**，不扣分，无须报名。实际合格人数不足时，按实际人数开奖。机器人、自身、退群或被封禁成员不参与；门槛为0时，也仅覆盖已产生积分记录的用户，无法枚举所有历史群成员。

候选名单按 Base 区块哈希确定顺序后逐个核验，选出合格用户。结果与候选顺序持久化，重复处理同一命令不会重抽。群内结果显示发起人，以及需审批的空投同意人的姓名与 ID，并通过用户提及链接 @ 发起人及所有中奖者（无用户名也可提及）；由管理员发放奖品。无人满足条件时向发起人提示。

### Base 区块唯一性

新空投从 Base 主网 RPC `https://mainnet.base.org` 获取最新完整区块（`latest`）哈希和高度；失败时尝试 `https://base-rpc.publicnode.com`。核验链 ID 8453，拒绝超过60秒的旧区块。Base 完整区块约2秒产生一次，不使用尚在变化的 pending/Flashblock。两个来源均不可用时不创建空投，不使用本地随机数替代。一个区块哈希只允许创建一次空投（跨管理员生效，空结果也占用此区块），须等下一个区块才能再发起。

候选人按 `SHA256("airdrop-v1|" + 区块哈希 + "|" + 十进制用户ID)` 升序排列，哈希相同则按用户ID升序，依序核验并选择第一个符合条件者。创建时的候选顺序、区块高度、区块哈希、来源、候选名单摘要和结果存入数据库；重试不会更换区块或重抽。摘要为 `SHA256` 对升序用户ID数组紧凑JSON（无空格）的计算结果。

结果展示区块高度、完整哈希和候选名单摘要。已知区块是可预测的公开种子；该方案用于确定性与去重，不等同于先锁定名单、再使用未来区块的不可预知抽奖。已创建空投固定使用创建时观察到的区块，不随链重组或来源节点进度变化改写结果。

历史 BTC 空投保留原链和原哈希；新空投使用 Base，同一条链同一区块只允许创建一次空投。

## AI 问答

- `/ai 你的问题`：直接问答；普通成员每分钟可调用一次，管理员不限。
- 回复一条消息后发送 `/ai`：让 AI 回答或解释该条消息；`/ai 总结一下` 可附加要求。
- - 支持引用文字和媒体说明，不识别图片本身。
- 群内触发时会附带**最近的群聊记录**（默认最近约 6 小时内最多 50 条、累计不超过 6000 字，按时间从早到晚排列），用于理解指代和上下文（例如「上面那个是什么」）。私聊触发不带群聊记录。
- 群内及机器人私聊可用；私聊同样核验用户属于管理群且完成验证。
- 普通成员默认每人每60秒接受一次请求（`AI_COOLDOWN_SECONDS` 可按群调整；群内和私聊共享，重启保留），管理员无此冷却。设为 0 可关闭冷却。接受后即占用额度，上游失败仍保留冷却。
- AI 请求后台运行，最多4个并发，其余排队，不阻塞群管与验证。已接收的同一消息不会重复调用；长回答拆分并回复原消息。模型 Markdown（标题、加粗、斜体、列表、引用、链接、代码块）会转成 Telegram HTML 后再发送；无法解析的标记按纯文本转义。
- 每条成功的 AI 回答末尾标注上游实际返回的模型 ID；上游未返回时显示部署配置的模型 ID。
- 使用 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 配置；模型列表确认 ID 为 `grok-4.7`。
- 管理员无限调用指免每分钟额度；上游服务限流及后台并发能力仍适用。

群内所有签到请求均自动删除用户原消息，包括成功、重复签到、头像不可见或验证失败；机器人的结果、警告提示保留。

### 积分查询展示范围（当前规则）

积分详情和排行榜仅在机器人私聊展示，仅支持 `/points` 和 `/rank`。群内触发时只显示私聊跳转按钮；点击后通过 start 参数直接打开相应查询。存在多个已启用群时，私聊查询会先让用户选择群组，结果标明群名并核验该群成员身份。签到仍在群内，成功提示仅显示本次获得的积分，不展示累计余额。

签到、积分、排行榜统一在处理和提示后删除用户原消息，群内及私聊均适用；机器人结果和警告提示保留。

封禁（管理员 `/ban`、累计三次警告自动封禁等）统一显式传入 `revoke_messages=True`，由 Telegram 删除被封禁成员的全部群消息；封禁成功后同步删除该成员的本地 AI 聊天上下文缓存。不会追溯批量封禁历史成员。

## 用户名与数字 ID

- `/ban`、`/unban`、`/warn`、`/mute`、`/unmute`、`/warnings`、`/resetwarn` 的目标支持 `@用户名`，原有管理员权限不变。
- 显式填写的 @用户名优先于回复目标；`/mute @name 30` 禁言 30 分钟。
- 仅解析已收录的用户名，每次通过 Telegram 重新核对当前用户名。未收录时请让该成员发言或回复其消息执行；无法核实则不执行管理操作。

## 私聊解封申请（2026-09-21）

群主收到的申请和待处理申请列表显示申请人昵称（可点击提及）、@用户名及数字 ID；未设置用户名时仍可通过昵称提及申请人。

被拉黑的用户私聊机器人发送 `/appeal 理由`；也可先发 `/appeal`，再发一条文字理由（最多 1000 字），`/cancel` 取消填写。发送 `/start` 会显示申请入口。

申请持久保存后通知当前群主，群主点击「批准解封」或「拒绝申请」。只有当前群主有处理权限；群主私聊 `/appeals` 可查看最早的 20 条待审申请，处理后再次查看下一批。群主需要先私聊启动机器人，才能接收私信；通知失败每 5 分钟重试。

待审期间不可重复提交，每人 24 小时最多提交一次。批准后解除 Telegram 封禁及本地黑名单、清零警告，私聊通知用户重新申请入群并完成验证。拒绝不会解除封禁，结果会私聊反馈。封禁记录发生变化时旧申请失效；Telegram 解封失败则保留待审状态供群主重试。历史消息和积分不会恢复。


## 积分达标恭喜消息（2026-09-21）

达到 50 分（配置 `UPGRADE_POINTS`）时，在群内发送「第 N 位累计积分达到 50 分」的恭喜消息。达标通知独立于成员标签：已有自定义标签、管理员身份或没有标签管理权限都不妨碍发送；积分标签升级仍独立运行。

每位用户每个门槛仅登记一次序号，保存到 SQLite，重启、积分清零后再次达标不会重复编号。发送失败按一分钟间隔重试；定期检查并补发遗漏通知。恭喜消息保留在群内，不参与自动删除。黑名单和已离群成员不发送。历史补发优先使用已保存的升级时间排序；没有历史时间的记录按补录顺序编号。


## 操作日志（2026-09-22）

管理员在群内发送 `/audit`，查看最近 100 条全部操作日志（即使回复消息也不自动筛选）。发送 `/audit 数字ID` 或 `/audit @用户名`，查看该用户作为操作者或目标的最近 20 条日志。按时间、日志编号倒序排列，长结果自动分条发送；无效目标会提示错误。

AI 上下文规则：回复消息调用时，结合过滤后的近期群聊理解引用消息，优先回答当前问题与引用内容；普通群内提问使用触发消息之前的近期成员发言，过滤命令、积分别名和机器人通知。空 `/ai` 需补充问题或引用消息。

AI 图片分析：回复照片或 JPG/PNG/WebP 图片文件发送 `/ai`（可附问题），也支持图片说明中的 `/ai 问题`。同一相册的已记录图片会按顺序一起发送，最多 10 张、单张 10 MB、合计 20 MB；相册索引保留 24 小时，不保存图片内容。旧相册未收录的图片无法补回，可重新发送；引用中仍附带的单张图片可直接读取。图片下载失败会提示，不会退回只解释标题。
